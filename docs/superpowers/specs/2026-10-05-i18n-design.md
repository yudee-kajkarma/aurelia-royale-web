# Internationalisation: six languages for the Aurelia Royale storefront

Date: 2026-10-05
Status: approved, ready for implementation planning

## 1. Intent

The client needs the Aurelia Royale storefront available in six languages:
English (current), French, Italian, German, Dutch and Spanish. English keeps
its present URLs unchanged; the five other languages are served under a locale
prefix (`/fr`, `/it`, `/de`, `/nl`, `/es`).

The bulk of the content is 99 blog articles whose text is currently hardcoded
in `src/app/blog/<slug>/page.tsx`. Translation is performed by an OpenAI
command-line script run from the repo, modelled on the working implementation
in `D:\Projects\uniglo-diamonds-web`.

Success means: all six languages live; English SEO unchanged; blog content
authored once in English and translated by script; no hand-translation.

### In scope

- The 99 blog articles, their SEO metadata and structured data, and the
  `/blog` listing cards.
- Storefront static UI: home, about, contact, shop catalogue, product detail,
  cart, checkout, header, footer, newsletter.
- Account and auth flows: login, register, verify-OTP, reset password,
  profile, orders, payments, wishlist, tickets.
- Bounded display label sets rendered frontend-side, e.g. the `label` fields
  of `SHOP_CATEGORY_TILES` in `src/services/products/product-category.ts`.

### Out of scope (decided, not deferred by omission)

- **Product content from the backend.** `title`, `description`, `details` and
  `tags` on the `Product` model stay English in every locale. A Spanish shop
  page will show Spanish UI chrome around English product names. This is the
  client's explicit decision. Localising it would require per-locale fields on
  the Mongo schema, admin UI work and a separate translation path.
- **The admin panel** (`src/app/admin/**`, ~3,800 lines). English only. It
  stays outside the locale route tree.
- **Currency and prices.** `PriceDisplay.tsx` keeps US formatting and the `$`
  symbol in all six locales. The store charges in USD, so it displays in USD.
  Real multi-currency is a separate project (FX source, per-currency price
  fields, cart/checkout/order totals, payment-gateway currency support).
- **Localised slugs.** Slugs stay English in every locale, so the 16 existing
  redirects in `next.config.ts` keep working and hreflang stays mechanical.
  Because `registry.ts` centralises slugs, adding per-locale slugs later is a
  data change rather than a refactor.

### Locales

| Code | Language | Prefix |
|---|---|---|
| `en` | English | none (default) |
| `fr` | French | `/fr` |
| `it` | Italian | `/it` |
| `de` | German | `/de` |
| `nl` | Dutch | `/nl` |
| `es` | Spanish | `/es` |

## 2. Findings that shape the design

Measured in the current codebase, not assumed:

- **99 blog folders, 44,698 lines of TSX.** All 99 declare `export const
  metadata` (none use `generateMetadata`), all 99 declare `articleSections:
  ArticleSection[]`, all 99 render `DynamicArticle` and `RelatedArticles`, and
  none use `BlogPageWrapper`/`BlogDetailLayout`.
- **Blog content is already structured data,** not prose JSX. Block type
  counts across all 99: `paragraph` 9,765, `image` 338, `table` 294,
  `bullet-list` 118, `cta-banner` 99, `faq` 98, `callout` 38,
  `numbered-list` 29.
- **The data is pure static literals.** No backticks, template literals or
  spread expressions anywhere in the 99 files. AST extraction is therefore
  lossless and mechanically verifiable.
- **The hero is structurally identical in all 99** (`bg-[#e8e5dc] py-16`,
  eyebrow `<span>` → `<h1>` → subtitle `<p>` carrying a published date).
- **The eyebrow is ~7 recurring category labels**, not 99 unique strings
  ("Coloured Stones and Diamonds", "Certification and Diamond Quality",
  "Buying Lab-Grown Diamond Jewellery", "Lab-Grown Diamond Education",
  "Product-Category Guides", "Jewellery Care and Maintenance", …).
- **62 of the 99 have a `schemaMarkup` JSON-LD graph containing a `FAQPage`
  that duplicates the `faq` block text verbatim** — each question string
  appears twice in the file. Generating JSON-LD from content removes ~25–30%
  of translation volume and a permanent drift source.
- **Listing cards live separately** in `src/data/blogs.data.ts` (99 entries:
  `title`, `date`, `author`, `excerpt`) — exactly matching the 99 folders, with
  no duplicates and no orphans.
- **Non-blog TSX is ~14,200 lines**, of which admin is ~3,800.
- **Blog body text is ~1.67M characters**, roughly 420K input tokens per
  target language.
- **Next.js is 16.2.2.** `middleware.ts` is deprecated and renamed to
  `proxy.ts` (confirmed in `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/proxy.md`:
  "The `middleware` file convention is deprecated and has been renamed to
  `proxy`"). There is no `middleware.md` in the bundled docs.
- **`next.config.ts` sets `trailingSlash: true`.** next-intl 4.13.1 supports
  this: its plugin reads `nextConfig.trailingSlash` and its middleware calls
  `normalizeTrailingSlash` when building alternate links. Supported, but smoke
  tested in phase 0 before the structure is committed to.
- **`PriceDisplay.tsx` is the single place prices are formatted** (hardcoded
  `$` and `toFixed(2)`). Left unchanged per the scope decision above.
- **The reference implementation matches closely.** `uniglo-diamonds-web` runs
  next-intl 4.13.1 with `localePrefix: "as-needed"`, `src/app/[locale]/`, a
  slug→namespace `registry.ts` feeding one shared `blogs/[slug]/page.tsx`
  (111 lines), and `scripts/i18n/translate.mjs` (27 KB). Its `registry.ts`
  comments document that it ran this exact folder-to-registry migration.

## 3. Architecture

### 3.1 Locale routing

`src/i18n/routing.ts` is the single source of truth:

```ts
export const routing = defineRouting({
  locales: ["en", "fr", "it", "de", "nl", "es"],
  defaultLocale: "en",
  localePrefix: "as-needed",
  localeDetection: false,
});
```

`localePrefix: "as-needed"` produces exactly the required URL rule: English at
`/blog/4cs-of-lab-grown-diamonds/`, other locales at
`/es/blog/4cs-of-lab-grown-diamonds/`.

`localeDetection: false` is deliberate. With detection on, a German-browser
visitor hitting the English homepage is silently redirected to `/de/`, which
changes what existing English traffic and crawlers see at `/`. Language choice
is explicit, via a header switcher.

`src/i18n/navigation.ts` exports locale-aware `Link`, `redirect`,
`usePathname` and `useRouter` via `createNavigation(routing)`. All in-scope
components import navigation from here instead of `next/link`, so internal
links stay in the current locale automatically. Internal `href` values in
content are written **without** a locale prefix (`/shop/`, not `/es/shop/`).

`src/proxy.ts` — named `proxy.ts`, not `middleware.ts`, per Next 16 —
default-exports `createMiddleware(routing)`. Its matcher excludes `api`,
`_next`, static files, `sitemap.xml`, `robots.txt` and `admin`.

`next.config.ts` wraps its existing export in
`createNextIntlPlugin("./src/i18n/request.ts")`, keeping `trailingSlash`, the
`images` config and the redirects intact. The plugin reads `trailingSlash` from
this config, which is how next-intl learns to normalise it.

### 3.2 Route tree

18 of the 19 folders in `src/app/` move under `src/app/[locale]/`: `about`,
`account`, `blog`, `cart`, `checkout`, `contact`, `home`, `login`, `orders`,
`payments`, `profile`, `register`, `reset-password`, `shop`, `shop-details`,
`tickets`, `verify-otp`, `wishlist`. Only `admin` stays at `src/app/admin/`.

`src/app/layout.tsx` splits in two:

- **Root layout** keeps the four `next/font` declarations, `metadataBase`, the
  `viewport` export and `globals.css`.
- **`src/app/[locale]/layout.tsx`** sets `<html lang={locale}>`, calls
  `setRequestLocale(locale)`, wraps children in `NextIntlClientProvider`, and
  holds the existing provider stack (`AuthProvider`, `WishlistProvider`,
  `CartProvider`), `Header`, `Footer`, `Toaster` and the back-to-top link.

`src/app/page.tsx` (currently `export { default } from "@/app/home/page"`)
becomes `src/app/[locale]/page.tsx`.

Imports use the `@/` alias throughout, so moving route folders does not
require import rewrites outside the moved files themselves.

### 3.3 Two content stores

This diverges deliberately from the reference implementation. uniglo's
`messages/en.json` is 2.5 MB and `de.json` 2.8 MB because blog bodies live in
the global message bundle, which `getRequestConfig` loads on every request for
every page. At 99 articles Aurelia would land in the same place. So:

**UI strings → next-intl.** `messages/<locale>.json`, namespaced per
page/component (`Header`, `Footer`, `HomePage`, `ShopPage`, `CheckoutPage`,
`blogCategories`, `blogCards`, `shopCategories`, …). A few hundred keys, ~30–60 KB per
locale. Loaded via `src/i18n/request.ts` (`getRequestConfig`), with
`getMessageFallback` returning `[MISSING: <path>]` and `onError` logging
`MISSING_MESSAGE` rather than throwing, so one absent key never 500s a page.

**Blog bodies → plain per-locale JSON, loaded on demand.**
`content/blogs/<slug>/<locale>.json`, read server-side by the blog route and
passed to `DynamicArticle` as a prop.

Blog content is *not* next-intl messages. `DynamicArticle` already renders from
a typed data prop, so blog bodies need no message machinery: they are data.
One request loads one ~20 KB file instead of a multi-megabyte bundle, and the
JSON stays type-checked against the existing `ArticleSection` type.

### 3.4 Blog file shape

`content/blogs/<slug>/<locale>.json`:

```json
{
  "metaTitle": "Lab-Grown Diamond 4Cs: Cut, Colour, Clarity & Carat",
  "metaDescription": "Learn how cut, colour, clarity and carat affect …",
  "category": "labGrownDiamondEducation",
  "title": "What Are the 4Cs of Lab-Grown Diamonds?",
  "subtitle": "Cut, Colour, Clarity & Carat Explained",
  "datePublished": "2026-07-15",
  "dateModified": "2026-09-10",
  "heroImage": { "src": "…", "alt": "…", "width": 1600, "height": 900, "caption": "…" },
  "sections": [ … ],
  "faqs": [ { "question": "…", "answer": "…" } ]
}
```

Notes on specific fields:

- `category` is a **key** into the shared `blogCategories` namespace, not
  prose. The ~7 labels translate once instead of 99 times.
- `datePublished` / `dateModified` are ISO dates formatted per locale at
  render time, yielding `15 luglio 2026` and `15. Juli 2026` for free. No date
  strings are translated.
- `sections` keeps the existing `ArticleSection[]` shape verbatim, so
  `DynamicArticle` needs no changes to its block handling.
- `faqs` is the single home for FAQ text. The `FAQPage` JSON-LD is generated
  from it.

### 3.5 Blog extraction

`scripts/i18n/extract-blogs.mjs` uses the TypeScript compiler API to read each
`src/app/blog/<slug>/page.tsx` and emit `content/blogs/<slug>/en.json`:

1. Locate the `metadata`, `articleSections` and `schemaMarkup` initialisers
   and the hero JSX strings.
2. Convert the object literals to JSON.
3. **Refuse to run** on any file where a value is not a literal (identifier,
   template literal, call, spread, computed property). A surprise cannot be
   silently mangled; the script fails loudly and names the file and node.
4. Derive `category` by matching the extracted eyebrow text against the
   `blogCategories` label set, failing on an unrecognised value.
5. Derive `datePublished`/`dateModified` from the `schemaMarkup` where present,
   else from `src/data/blogs.data.ts`.

**Verification gate:** two checks per blog, both independent of the extraction
logic — every string leaf in the extracted `sections` must appear verbatim in
the raw source text, and an independent AST count of `type`-bearing object
literals must equal the extracted block count. Comparing the extractor's output
to itself would establish only determinism. All 98 must pass before any folder
is deleted.

`schemaMarkup` is *not* extracted as translatable content — it is dropped and
regenerated. Before the first deletion, a one-off diff confirms the generated
graph matches the handwritten one for a sample of blogs across both the
62-with-schema and 37-without groups.

### 3.6 Blog rendering

`src/lib/blogs/registry.ts` lists the 99 slugs. `src/app/[locale]/blog/[slug]/page.tsx`
(~150 lines) replaces all 99 folders: `generateStaticParams` over slugs × 6
locales, `generateMetadata` reading the same JSON for `metaTitle`,
`metaDescription`, the locale-aware canonical and `alternates.languages`, and a
default export rendering hero → `DynamicArticle` → `FAQSection` →
`RelatedArticles` → `NewsletterSection`.

`src/lib/blogs/schema.ts` exports `buildBlogSchema(content, slug, locale)`,
generating the `Organization` / `WebSite` / `ImageObject` / `WebPage` /
`BlogPosting` / `BreadcrumbList` / `FAQPage` graph from the translated content.
FAQ text exists once, translates once, cannot drift.

Rollout is safe because a real route folder wins over the `[slug]` catch-all in
the Next router. English folders are deleted one at a time with verification
between, and any single blog can be reverted by restoring one folder.

`src/data/blogs.data.ts` loses its `title`, `author` and `excerpt` fields to
`messages/<locale>.json` under a `blogCards` namespace keyed by slug, keeping
`slug`, `image` and `date` in code. `NO_IMAGE_SLUGS` and the sort order in
`src/app/[locale]/blog/page.tsx` are unaffected.

One real inconsistency to resolve during phase 2:
`/blog/advantages-of-lab-grown-diamonds/` has BOTH a folder and a permanent
redirect pointing away from it in `next.config.ts`, under the "Content
consolidation" comment. The redirect fires at the edge before routing, so that
page is already unreachable today, while its listing card still links to it.

The redirect is authoritative and the folder is leftover. That slug is therefore
excluded from extraction, the registry, `blogs.data.ts` and the sitemap, with
the exclusion derived from the redirect source list so it cannot drift. Servable
blogs: **98**. Translated content files: 98 x 5 = **490**. A sitemap must list
canonical 200 URLs, so including a redirecting URL six times would be an SEO
defect, and translating six unreachable pages would waste money.

## 4. Translation pipeline

`scripts/i18n/translate.mjs` is adapted from
`D:\Projects\uniglo-diamonds-web\scripts\i18n\translate.mjs`.

### How the existing script stays safe

The JSON structure is never sent to the model. The script walks the object,
collects scalar leaves tagged with their path, and sends a batch as
`{"0": "text", "1": "text"}` — index keys only. Results are written back at
recorded paths, so keys, nesting and array lengths cannot change. Independently,
`PROTECTED_KEYS` holds back `type`, `href`, `src`, `url`, `slug`, `id`,
`width`, `height`, `image`, `namespace`, and four `NON_PROSE` regexes drop
URLs, internal paths, emails and pure numerics regardless of key. Batching is
`BATCH_CHARS` 6,000 / `BATCH_ITEMS` 50, `CONCURRENCY` 4, `MAX_ATTEMPTS` 3.
Glossary rows are injected only when the term occurs in that batch.

Translations land in `scripts/i18n/staging/<locale>/` and reach
`content/`/`messages/` only via a separate `merge` step. Staging is
gitignored.

### Required adaptations

1. **`PROTECTED_KEYS` gains `shopHref`, `contactHref` and `theme`.**
   `cta-banner` carries `shopHref`/`contactHref`; `callout` carries
   `theme: "cream" | "pine" | "gold-border"`. Without this the script would
   translate `"cream"` to `"crème"` and break callout styling. This is the
   highest-risk line in the adaptation and gets a dedicated assertion: the dry
   run fails if any `theme`, `shopHref` or `contactHref` value appears in the
   translatable set.
2. **File mode alongside namespace mode.** The reference script only addresses
   namespaces inside `messages/*.json`. Aurelia also needs
   `content/blogs/<slug>/<locale>.json`.
3. **`merge` needs no `--after` for blogs.** The anchor argument exists only to
   position a namespace inside a shared monolith. Per-blog files have no
   ordering problem, so the whole `anchor key not found` failure class
   disappears for blog content. `--after` is retained for `messages/*.json`
   namespace merges.
4. **A batch driver for 99 articles:** `translate blogs --all`, resumable (the
   existing skip-if-staged behaviour provides this), printing per-blog progress
   and a running token/cost tally so a run can be interrupted and resumed
   without re-spending.
5. **Locale constants updated.** The reference script hardcodes
   `TARGET_LOCALES = ["nl","fr","de","es","it"]` and a `LOCALE_NAMES` map;
   both are repointed at `src/i18n/routing.ts` so the locale list has exactly
   one definition in the repo.
6. **Glossary seeded from uniglo's `glossary.json` and extended.** Theirs is
   diamond-focused and matches the domain (`clarity`, `carat`, `cut`,
   `colour`, lab-grown terminology). Aurelia adds jewellery-construction terms
   its blogs rely on: `bezel`, `pavé`, `tennis bracelet`, `huggie`,
   `station necklace`, `hallmark`. `IGI` and `GIA` are verbatim-protected
   tokens.

### Commands

| Command | Cost | Purpose |
|---|---|---|
| `models` | free | List model IDs the key can use |
| `terms "<term>"` | free | Show how a term is currently translated per locale |
| `check [<target>]` | free | Scan for glossary violations |
| `translate <target> --dry` | free | Show what would be sent and held back |
| `translate <target>` | paid | Translate into all five locales, to staging |
| `translate blogs --all` | paid | Batch-drive all 99 blogs, resumable |
| `translate <target> --locales fr,it --force` | paid | Redo named locales |
| `merge <target>` | free | Move staged translations into `content/`/`messages/` |

`OPENAI_API_KEY` and `OPENAI_MODEL` live in `.env.local` (gitignored). There is
no default model, so a wrong model name fails before a paid run rather than
during one.

### Review policy

Staging and the QA validators are retained, but launch is **not** gated on
human review of all 490 files. Files whose validators come back clean merge and
ship. Files carrying a flag — `shape`, `link`, `token`, `untranslated`,
`typography`, `glossary`, `glossary-miss` — are fixed before merge. After
launch, the highest-traffic articles are reviewed first by editing
`content/`/`messages/` directly.

This accepts machine-grade wording on low-traffic articles at launch in
exchange for shipping all six languages in days rather than blocking on roughly
80 hours of native-speaker time.

## 5. SEO

- **Canonicals.** The hardcoded absolute `alternates.canonical` in all 99 blog
  files is replaced by a generated locale-aware canonical. Every page is
  self-canonical within its locale.
- **hreflang.** Every page emits `alternates.languages` for all six locales.
  next-intl's middleware also emits `Link` alternate headers.
- **Sitemap.** `src/app/sitemap.ts` grows from ~104 entries to 618 — 4 static
  pages, the blog index and 98 servable articles, each × 6 locales, each
  carrying its `alternates.languages` block — with product entries appended from the live
  API as today. Well under the 50,000-URL limit.
- **Redirects.** The 16 entries in `next.config.ts` have sources like
  `/blog/old-slug/`, which do not match `/es/blog/old-slug/`, so a non-English
  visitor following an old inbound link currently 404s. The locale variants are
  **generated programmatically** from the existing list: 16 hand-maintained
  entries become 96 generated ones, with no new maintenance burden.
- **`<html lang>`** is set per locale in `[locale]/layout.tsx`.
- **`robots.ts`** needs no change.

## 6. Rollout

Seven phases. Each is independently verifiable, and the site stays English-only
until phase 5, so nothing user-visible changes until content is ready.

| # | Phase | Done when |
|---|---|---|
| 0 | Spike: next-intl + `proxy.ts` + `trailingSlash` on a throwaway branch | `/about/` and `/es/about/` both resolve, with and without trailing slash |
| 1 | i18n scaffolding; 18 folders under `[locale]`; layout split; language switcher | Build passes and every existing URL behaves identically |
| 2 | Blog extraction → 99 `en.json`; shared route; registry; generated JSON-LD | Round-trip check passes for all 99; English folders deleted |
| 3 | Static UI strings → `messages/en.json` | No bare user-facing literals left in in-scope components |
| 4 | Script adaptation; glossary; dry runs | `--dry` shows correct held-back counts on every blog, and the `theme`/`shopHref`/`contactHref` assertion passes |
| 5 | Paid translation runs; merge clean, fix flagged | All six locales present for all in-scope content |
| 6 | SEO wiring; verification; launch | Crawl of every route × 6 locales clean |

Phase 2 carries the real risk. Everything else is mechanical.

**Effort estimate:** roughly 8–11 focused working days, phases 2 and 3 being
the bulk. OpenAI spend for the full corpus is tens of dollars, one time.

## 7. Verification

Four automated gates, not visual inspection:

1. **Per-blog AST round-trip diff.** Emitted JSON re-parsed and deep-compared
   against the source literal. All 99 pass before any folder is deleted.
2. **`npx tsc --noEmit` and `npm run build`.** The blog JSON is typed against
   `ArticleSection`, so a malformed block fails the type check.
3. **`scripts/i18n/check-i18n.mjs`.** Asserts every blog has all six locale
   files, that their shapes are identical, that no `category` value is missing
   from `blogCategories`, and that no merged file contains `[MISSING:`.
4. **Route crawl.** Every in-scope route × 6 locales returns 200 with the
   correct `<html lang>` and a complete hreflang set; the 96 generated
   redirects each return 308 to the right locale-prefixed target; an unknown
   locale (`/pt/`) 404s; and a wrong-case locale (`/EN/`) redirects to the
   canonical lowercase form rather than 404ing, which is next-intl's
   case-insensitive matching working as intended.

Then visual spot-checks on the highest-traffic articles in each language, and a
check that a Spanish page's internal links stay inside `/es/`.

## 8. Consequences accepted

- Spanish/German/etc. shop and product pages show **English product names and
  descriptions** inside translated UI chrome, until and unless backend
  localisation is scoped.
- Non-English URLs carry **no local keywords**, since slugs stay English.
- Prices read **`$1,299.00`** in every locale.
- Low-traffic articles launch with **machine-grade wording** in the five
  non-English languages.
- Blogs remain **repo-authored**. Adding one means a JSON file and a deploy,
  not an admin screen. Moving blogs into the backend as a CMS remains available
  as a later project.
